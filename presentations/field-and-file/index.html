04 / Resolve uncertainty without weakening fairness

“Show me the facts. Let me hear the farmer.”

Inspection establishes a scoped finding. An accountable official determines the consequence.

The Inspector

Which question needs a visit?

A human approves the task and proportionate ground or authorised drone route.

Task-scoped access, raw evidence and capture lineage. Lock the independent finding before revealing model suggestions.

Two separate control lanes

Targeted ≠ random

Targeted inspectionResolve a risk
Probability sampleTest the system

Random validation includes apparently consistent cases. Farmer photos cannot replace independent sample observations.

The Decision Guardian

Was the farmer heard?

Notice, evidence access, response, human review and a reasoned decision with an appeal route.

No LLM-issued sanctions, reductions or entitlement decisions.

Public-service value: focus field capacity while retaining independent assurance and due process.
Proposed control design; actual national procedures, sampling targets and drone permissions need approval.

07 / How we organised the work

The service agents are not the build team.

Nine delivery roles turn a case brief into scoped artifacts, fixed handoffs and explicit decisions.

Development-team roles in .github/agents

Azure architect

ML / data

Infrastructure tester

Compliance reviewer

Profiles, shared skills, phase prompts and assignments are defined. Actual host/model behaviour is not guaranteed by configuration.

One owner per artifact

Independent work can run in parallel after contracts freeze. Reviews return to the owner; they do not silently rewrite the baseline.

Risk-fit model routing

Lower-tier GPT for clerical work only. Higher-capability technical roles; distinct security/compliance reviewer defaults. Technical documentation escalates.

Important limit: coordination and gate enforcement are procedural, not a fully automated delivery platform.

CASE → SCOPE

Targets + ownership

Brief, personas, decisions and bounded assignment.

DESIGN → RELEASE

Review + approval

Feasibility, actual plan, fixed revision and human authority.

BUILD → EVIDENCE

Delivery sequence agreed: infrastructure → Azure ML → application/runtime. Separate scopes, not one deployment.

08 / Strong evidence, proportionate to the experiment

Compliance is a design input—not a stamp.

The repo preserves requirements and findings, but the current PoC is intentionally technical and uncertified.

Recorded

Design released

Exact design/plan, feasibility, scoped reviews and user local-authoring approval.

Blocked

Locally validated

Compiler success is not enough. Effective author contracts fail; independent acceptance is pending.

Not run

Deployment ready

Actual target, identity, scope, funding, authorised validation and inspected what-if.

Not run

Operationally verified

Separately approved execution and observed behaviour in the real environment.

Traceability over confidence

Source precedence, versioned decisions, preserved bytes/hashes, non-author reviews and honest PASS / FAIL / BLOCKED / NOT RUN labels.

Deliberate PoC boundary

Historical security/compliance requirements remain reference evidence. Certification campaigns are not PoC outcomes; scoped safety and later applicable obligations still matter.

Review/test loops stop at five total attempts. Preparation accounting was clarified separately; it does not reset a failing workload check.

No claim of GDPR, AI Act, CAP or production certification. Source summaries are not legislation.

10 / Human in the loop—twice

The human became the referee.

Customer decisions need human oversight by design. Engineering coordination also needed it—more than intended.

Implementation goal

“Produce a bounded technical PoC.”

Assurance demands

Different agents treated different evidence and approvals as prerequisites.

The accountable human

Clarified the goal.
Resolved conflicting interpretations.
Changed the authorised scope.

User’s retrospective
What helped

Explicit ownership, visible blockers, recorded decisions and no false deployment claims.

What cost time

Heavyweight standards, recursive coordination and a complex test evaluator.

1 / Fit assurance to risk

Set the experiment boundary before agents debate production-grade obligations.

2 / Automate facts first

Prefer simple deterministic checks; reuse tooling before building another evaluator.

3 / Escalate once, clearly

One conflict owner, a bounded decision and fewer routine human dispatches.

Learning: governance should make authority clearer—not turn the sponsor into the orchestration engine.
User reflection + recorded project blockers. Improvements are recommendations, not implemented policy or waived checks.
